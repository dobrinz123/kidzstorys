<task id="2">
<title>Insert the audioGenBatches table definition into convex/schema.ts</title>
<read_first>
- convex/schema.ts (locate the end of the audioJobs block — insert audioGenBatches immediately after it, still within the AUDIO GENERATION section)
</read_first>
<action>
Open `convex/schema.ts`. Locate the end of the `audioJobs` table (the line ending in `.index("by_batch", ["batchId", "status"]),`). Immediately after that line and before the `// ============ LEGACY STORIES` comment, insert the following block exactly:

```typescript
  // Batch run tracking
  audioGenBatches: defineTable({
    batchId: v.string(),             // unique batch identifier, e.g. "batch_1711234567890"
    locales: v.array(v.union(v.literal("en"), v.literal("ro"))),
    status: v.union(
      v.literal("queued"),
      v.literal("processing"),
      v.literal("paused"),
      v.literal("completed"),
      v.literal("failed")
    ),
    totalJobs: v.number(),
    completedJobs: v.number(),
    failedJobs: v.number(),
    createdAt: v.number(),
    completedAt: v.optional(v.number()),
  })
    .index("by_status", ["status", "createdAt"])
    .index("by_batchId", ["batchId"]),

```

Notes:
- `audioJobs` uses `"by_status"` on `["status"]` and `audioGenBatches` uses `"by_status"` on `["status", "createdAt"]`. Convex index names are scoped per-table — this is valid.
- `by_batchId` is required so Phase 3's `startAudioBatch` mutation can look up a batch by its string ID without a full table scan.
- The trailing comma after `.index("by_batchId", ...)` is required because tables follow.
</action>
